# MatchCart — этап 5: UI/UX и готовность локального демо

База: 47d7526. Дата проверки: 27 октября 2026, Asia/Tbilisi.

## Аудит и решение

Раньше форма Assistant, технические пояснения, цены и действия имели почти одинаковую визуальную значимость. Preferences выглядели длинным списком. В карточках итог терялся среди строк расходов. На мобильном лишняя верхняя навигация дублировала шаги.

Новая система: спокойный светлый фон, белые поверхности, один тёмно-зелёный акцент, выраженный заголовок, компактные статусы. Без градиентов, внешних шрифтов, новых UI-библиотек и имитации AI. Небольшие SVG-иконки написаны в коде; они декоративные и скрыты от screen reader. Системный Segoe UI/Arial не требует загрузки шрифтов из сети.

Токены в globals.css: canvas/surface/ink/muted/accent, border/control-border, warning/danger, интервалы, типографические размеры, радиусы, тень. Фокус имеет контрастную рамку 3 px. Элементы управления имеют высоту от 44–50 px. Reduced motion отключает переходы; предусмотрены increased contrast и forced colors.

## Изменения экранов

- Assistant: выразительный главный экран с объяснением полного решения, настоящая форма Meta, локальное превью выбранной фотографии и удаление фото. До Analyze файл не отправляется. Результат показывает бюджет, сроки, установку, режим и модель, если она извлечена. Неизвестная модель остаётся неизвестной. Фото и blob URL не попадают в sessionStorage.
- Preferences: три визуальные группы — бюджет/сроки, подключение, подтверждение. Поля сгруппированы в две колонки на большом экране и одну на узком. Все исходные проверки, ID, I do not know и Advanced Settings сохранены.
- Comparison: первыми видны модель, статус, общий бюджет и полный итог. Затем доставка и мастер. Разбивка расходов и объяснения раскрываются отдельно. Повторяющиеся одинаковые отказы объединяются только при отображении; ответы движка не меняются. Техническая несовместимость обозначается отдельно от коммерческого отказа.
- Complete Solution: выбранный план с открытой разбивкой расходов и блоком следующих действий. Это локальный выбор для демонстрации, не оплата и не бронирование.
- Навигация: активный шаг, сохранённый прогресс, заголовок получает фокус после перехода. Ссылки на конкретные поля продолжают открывать Advanced Settings и фокусировать поле. При первой загрузке фокус не перехватывается.

Compatibility Engine, Recommendation Engine, Meta API, security, доменные модели и правила расчётов не изменялись. В интерфейсе повторно используется существующая проверка совместимости, чтобы правильно подписывать исключённые технически варианты. Нет новых коммерческих вызовов.

## Проверки

- npm test: 48 unit/integration-тестов.
- npm run test:e2e: 28 браузерных тестов, включая прежние сценарии и новые visual/accessibility-проверки.
- npm run typecheck и npm run build.
- Эталоны PNG: desktop 1440 px, mobile 390 px, фиксированная дата; A/B/C, несовместимость, Assistant, Preferences, итоговый экран, ошибки, обработка и результат AI.
- Проверка планшета 820 px; ширины 320 px с текстом 200% и 400%, включая выбранное полное решение. Горизонтальное переполнение устранено адаптивными контейнерами, отступами и декоративными пиктограммами, без скрытия содержимого страницы.
- Axe проверяет доступные правила WCAG 2 A/AA, 2.1 A/AA, 2.2 AA на обычных и заполненных состояниях. Сохранён полный сценарий клавиатурного выбора, проверены видимый фокус, error/status, направление фокуса, reduced motion и подписи.
- NVDA не найден в доступной среде. Живую ручную проверку NVDA не проводили. Полное соответствие WCAG не заявляется.
- Реальный Meta через обновлённый браузерный интерфейс: текст + доступная ранее замаскированная фотография, категория wifi-router, бюджет 15000 центов, перенос 150 в Preferences. В этом ответе deviceModel=null: интерфейс корректно показал необходимость уточнения, не подставляя модель. Приложение не использует заготовленные AI-ответы. Фикстуры с явными названиями используются только в E2E-тестах.

Эталоны получены в Windows/Chromium. На другой ОС системные шрифты могут дать отличия: эталоны для новой платформы нужно осмотреть и утвердить отдельно. Обычный прогон не обновляет эталоны. Обновление после осознанного изменения дизайна: npx playwright test visual.spec.ts --update-snapshots.

## Визуальная проверка

Запуск: npm run dev. Открыть http://localhost:3000.

1. Проверить новый Assistant на desktop и в мобильном режиме DevTools (390 px). Прикрепить замаскированную фотографию: появляется локальное превью, Remove photo очищает выбор.
2. Отправить реальный запрос с бюджетом $150. Проверить загрузку, сводку, отметки unverified и переход к Preferences.
3. Выполнить сценарий README с подтверждёнными ТЕСТОВЫМИ параметрами. Использовать earliest express test date, отображённую на странице; после 23:00 она учитывает следующий день обработки.
4. Убедиться в итогах $135.16 и $146.06, раскрыть расходы, выбрать Choose this plan, открыть Review selected solution.
5. Вернуть protocol=unknown: нет подтверждённых рекомендаций и кнопок выбора, есть жёлтый статус и инструкции.
6. Поставить $50: нет полного комплекта, отображаются причины и безопасные следующие действия без автоматического увеличения бюджета.
7. Проверить Tab/Shift+Tab/Enter, масштаб и видимые фокусы. Для демонстрации без Next dev-индикатора сервер после изменения next.config перезапускается автоматически.

Локальные PNG для просмотра сохранены в artifacts/stage5. Публичная готовность остаётся отдельным этапом: Upstash/Turnstile/Vercel не подключались, PUBLIC_LAUNCH_BLOCKED сохранён. Реальные магазины, оплата и бронирования не добавлялись.
